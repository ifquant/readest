现在 Readest “主要支持哪些特性”（按产品能力分层）
A. 阅读格式与阅读器内核
• 基础支持 EPUB / PDF 阅读（早期即明确）。(GitHub)
• PDF 侧加入更像“阅读软件”的交互：比如 Hand-tool（拖拽平移）。(GitHub)
• 对排版/脚注等深阅读细节持续补齐：如 popover 脚注、竖排文档弹窗适配、定义列表脚注支持等。(GitHub)
B. 标注/笔记（知识加工层）
• 早期就包含 笔记与高亮。(GitHub)
• 近期把标注系统做“产品化”：标注气泡直接渲染在正文上、点击即弹 note、可编辑高亮范围、标注导航栏，并有“快速高亮”等效率增强。(GitHub)
• 新增更像“编辑器”的工具：proofread（可直接替换书内文字）。(GitHub)
C. 内容获取与导入
• 从“本地导入”走向“在线书库接入”：支持 OPDS 浏览与下载，并持续增强兼容性（Calibre Web、Komga、自签名证书等）。(GitHub)
• 增加“可直接用”的内容入口：Standard Ebooks 精选书目、OPDS 即时搜索栏。(GitHub)
D. 书库管理（Library/Bookshelf）
• 早期就有“Library/Bookshelf”方向；后续开始补齐“管理动作”：如 Group Books、网格视图封面尺寸、封面导出目录等。(GitHub)
• 同步侧把“全库体验”做顺：强调 更快的 library syncing。(GitHub)
E. 多端同步与云（从能力到商业化）
• 2024 年底就引入 Sync API + Supabase 作为数据同步底座。(GitHub)
• 2025 年开始把“云状态”做成可见能力：每本书的 cloud backup status 可见。(GitHub)
• 进一步产品化/商业化：应用内一次性购买扩容云存储（IAP）、并配套更快的全库同步。(GitHub)
F. 语音与翻译（AI/辅助能力）
• TTS 在多个版本里持续增强：包括“Edge TTS 在部分地区被阻断”的修复、朗读体验优化（句间停顿减少）。(GitHub)
• 翻译能力向“可扩展架构”演进：出现 translator hook 以支持更多翻译提供方，并且 TTS 支持“译文朗读目标语言选择”。(GitHub)
G. 平台覆盖与系统集成
• 项目早期就走 Web + 桌面（Tauri） 的跨平台路线（当时还提到未来 iOS/Android）。(GitHub)
• 2024 年底开始补“桌面级体验”：文件关联、自动更新、滚轮翻页、页眉页脚等。(GitHub)
• 近期移动端也更“产品化”：iOS Files 直接打开、后台传输队列等。(GitHub)

产品化演进地图（从最早 Release 到现在）
我把时间线按“用户旅程主线：获取内容 → 管理书库 → 深阅读 → 知识加工 → 多端同步”串起来。 最早 Release：v0.7.9（11 月 30 日），最新：v0.9.97（1 月 10 日）。(GitHub) 且项目在 2024-12-06 就已有公开介绍帖（可作为“早期发布窗口”的旁证）。(GitHub)

1. 2024-11 ~ 2024-12：把“能用的跨端阅读器”跑通（MVP 成型）
   • v0.7.9（11/30）：核心能力就位——EPUB/PDF + 笔记/高亮 + 同步阅读进度。(GitHub)
   • v0.8.2（12/06）：开始明显“产品化桌面体验 + Web 化”
   ◦ 文件关联、滚轮翻页、自动更新、页眉/页脚开关，以及 “支持在现代浏览器运行”。(GitHub)
   • v0.8.3（12/12）：深阅读细节增强
   ◦ popover 脚注、竖排文档弹窗方向、加载额外字体、内置 demo library。(GitHub)
   • v0.8.5（12/24）：同步底座落地
   ◦ 引入 Sync API（Supabase），并补齐自定义 CSS（含非 ASCII）与“禁用点击翻页”等阅读控制。(GitHub)
   这一阶段的产品主线：“跨平台可用”优先于“极致功能”——先把导入阅读、翻页、脚注、字体、同步 API 这些最关键的骨架搭好。

2. 2025-05：从“有同步”走向“同步可见 + 翻译可扩展”
   • v0.9.43（05/19）：把同步做成用户可感知状态 + 翻译架构升级
   ◦ 每本书的 cloud backup status 可见（移动/桌面）。(GitHub)
   ◦ 通过 translator hook 支持更多翻译提供方（这对后续 AI/翻译生态很关键）。(GitHub)
   这一阶段的产品主线： 从“技术上能同步”进化到“用户能相信同步、能理解状态”；同时把“翻译”从单一实现升级为可插拔扩展点。

3. 2025-10：进入“商业化与体验深化”的拐点（云存储/IAP + TTS/阅读器效率）
   • v0.9.90（10/28）：一个非常“产品化”的组合拳
   ◦ Sync：更快的全库同步 + 一次性购买扩容云存储（IAP）。(GitHub)
   ◦ TTS：译文朗读可选目标语言。(GitHub)
   ◦ Reader：章节跳转快捷键、滚动更顺、搜索更准、导入错误信息更清晰；还能自定义高亮颜色。(GitHub)
   这一阶段的产品主线：“同步/云”变成可商业化模块；阅读效率（快捷键、搜索、导入反馈）与个性化（高亮色）一起补齐。

4. 2025-12：内容接入（OPDS）+ 系统集成（封面/缩略图）+ CJK/移动端完善
   • v0.9.94（12/01）：OPDS 与多项系统级特性落地
   ◦ OPDS 目录浏览与下载、PDF hand-tool、简繁转换、Windows Explorer 电子书封面缩略图、封面导出目录、网格封面尺寸等。(GitHub)
   • v0.9.96（12/19）：把 OPDS 做到“像产品”
   ◦ OPDS 即时搜索栏、Standard Ebooks 精选、Group Books；iOS Files 直接打开。(GitHub)
   这一阶段的产品主线： 从“读本地文件”明显迈向“内容入口 + 书库管理 + 系统整合”，并把中文/竖排等东亚语言体验拉到更高水位。

5. 2026-01：知识加工与工作流化（标注系统大升级 + 传输队列 + 校对）
   • v0.9.97（01/10）：把“阅读”推向“可工作流的知识处理”
   ◦ 标注气泡/即时 note、可编辑高亮范围、标注导航；
   ◦ 后台传输队列（上传/下载）；
   ◦ proofread 直接替换书内文本；
   ◦ TTS 句间停顿优化、OPDS/Komga/自签名证书等兼容继续补齐。(GitHub)
   这一阶段的产品主线： 从“阅读器”进一步向“学习/编辑工具”靠拢：标注的可见性、可导航性、可编辑性都补齐了，外加文件传输队列这种“重度用户必备”的工程化能力。

一句话总结：Readest 的“产品化主线”
它不是随机堆功能，而是很清晰地沿着这条链路长出来的：
跨端可用（Web/Tauri） → 阅读内核细节（脚注/竖排/字体/PDF） → 同步底座（Supabase） → 同步可见与可扩展翻译 → 云与商业化（扩容/IAP） → 内容入口（OPDS/Standard Ebooks） → 知识加工工作流（标注系统/校对/传输队列）。(GitHub)

如果你愿意把它做成“一张图”，我建议用 两条泳道 来画（更产品化、也更容易讲故事）：
1 用户旅程泳道：获取内容 → 管理书库 → 深阅读 → 标注/校对 → 同步/跨端
2 平台/商业泳道：Web/桌面/移动 → 系统集成 → 云存储/IAP → 生态（OPDS/翻译提供方）
