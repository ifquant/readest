# “校对模式”与文本替换功能分析

Readest 包含一个强大的“校对 (Proofread)”子系统，允许用户直接修正电子书中的错别字或版式谬误，甚至进行批量文本替换。

## 1. 原理：渲染管道拦截器

Proofread 功能并没有直接修改电子书的源文件（EPUB 压缩包），而是实现为一个 `Transformer` (`proofreadTransformer`)。

- 在 `foliate-js` 解析 HTML 资源并准备渲染之前，Proofread 拦截器会获取到原始 DOM 字符串。
- 它根据当前激活的**替换规则 (ProofreadRule)** 对 DOM 文本节点 (`TextNode`) 内容进行修改。
- 修改后的 HTML 被送入 WebView 渲染，因此用户看到的是“修正后”的版本。

## 2. 规则作用域

系统支持三种层级的规则，满足不同场景：

1.  **Global (Library)**: 全局生效。适用于修正通用的 OCR 错误（如将所有的 "l" 在数字上下文中修正为 "1"）。
2.  **Book**: 仅当前书籍生效。适用于特定本书的人名、地名修正。
3.  **Selection (Specific Range)**: 仅在特定的文本段落生效。基于 CFI (Canonical Fragment Identifier) 定位，用于修正某一处特定的排版错误。

## 3. 高级匹配逻辑 (`proofread.ts`)

### 3.1 正则表达式与规范化

- 系统支持 Regex 匹配，并自动处理 flag (如 `i` 忽略大小写, `u` Unicode 支持)。
- **智能边界** (`normalizePattern`): 如果用户输入纯单词（如 "Apple"），系统会自动包裹 `\bApple\b` 以避免匹配到 "Pineapple"。
- **多语言适配**: 针对 CJK（中日韩）等不使用空格分词的语言，系统实现了 `isValidMatch` 过滤逻辑，禁用默认的 `\b` 边界检查，转而判断相邻字符的 Unicode 类型，确保在 "我爱吃苹果" 中也能正确匹配 "苹果"。

## 4. 应用场景

- **纠错**: 遇到 OCR 识别错误的字（如把“日”识别成“曰”），用户选中并创建规则，后续阅读时自动修复。
- **T/S 转换补充**: 配合简繁转换功能，修正某些术语的地区习惯用法（如把“软件”批量替换为“软体”）。
- **TTS 优化**: 为 TTS 引擎创建发音修正规则（仅在 `onlyForTTS` 模式下生效），例如强制将“行”在特定词组下读作 "xíng" 而非 "háng"。
