# TTS 朗读体验优化分析

为了接近自然人声的朗读体验，Readest 在 v0.9.96 针对 TTS (Text-to-Speech) 的停顿节奏和 SSML 处理进行了多项微调。

## 1. 智能停顿控制 (`#preprocessSSML`)

TTS 引擎通常对标点符号非常敏感。为了优化听感，系统在送入引擎前会对文本进行预处理：

- **省略号优化**: 将连续的句点 `...` (`/\.{3,}/`) 或中文省略号 `……` 替换为多个空格。大多数 TTS 引擎会将空格处理为更自然的呼吸停顿，而不是生硬地尝试朗读符号或忽略它。
- **破折号处理**: 将 `–` 或 `—` 替换为逗号 `,`，强制引擎进行短停顿，模拟从句的语调变化。
- **标签清理**: 移除 `<emphasis>` 等可能导致某些引擎（如 EdgeTTS）产生不自然重读的 SSML 标签。

## 2. 状态机管理 (`TTSState`)

TTS 并非简单的“播放/暂停”。`TTSController` 维护了一个细粒度的状态机：

- `playing`: 正常播放。
- `paused`: 用户主动暂停。
- `stop-paused`: 停止并准备随时恢复。
- `backward-paused` / `forward-paused`: 跳转（上一句/下一句）后的临时暂停状态。

这种设计解决了“在播放时点击下一句，应该是直接播放下一句”与“在暂停时点击下一句，应该跳转但保持暂停”的交互逻辑冲突。

## 3. 多引擎平滑切换

系统支持 Web Speech API (浏览器原生)、Edge TTS (微软在线) 和 Native TTS (系统原生)。

- **预加载 (`preloadNextSSML`)**: 为了防止网络引擎（EdgeTTS）在切句时卡顿，控制器会提前获取下 4 个段落的 SSML 并预热缓存。
- **错误回退**: 当网络引擎失败时，会自动降级或报错，如果不报错则记录 `nossmlCnt`，连续多次无声则自动跳过，防止卡死。
