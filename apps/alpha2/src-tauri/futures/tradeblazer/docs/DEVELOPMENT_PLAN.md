# TradeBlazer 脚本编译器开发计划

## 1. 项目概述

TradeBlazer 脚本编译器是一个用于解析和执行 TradeBlazer 交易策略脚本的工具。该项目旨在提供一个完整的编译器架构，包括词法分析、语法分析、语义分析和脚本解释执行功能。

## 2. 系统架构

当前系统采用典型的编译器前端架构，包含以下核心组件：

1. **词法分析器(Lexer)**：将脚本文本转换为 Token 流
2. **语法分析器(Parser)**：将 Token 流转换为抽象语法树(AST)
3. **语义分析器(Semantic)**：对 AST 进行语义检查，验证脚本合法性
4. **抽象语法树(AST)**：表示脚本的语法结构
5. **解释器(Interpreter)**：执行 AST 表示的脚本逻辑

## 3. 核心功能模块

### 3.1 词法分析器(Lexer)

**功能**：将 TradeBlazer 脚本文本转换为 Token 序列。

**主要特性**：

- 支持基本关键字：if, else, for, function, return, var, series, true, false
- 支持标识符、数值字面量、字符串字面量
- 支持各类运算符和分隔符,包括，=， +， -， \*， /， %， <， >， <=， >=， ==， !=
- 支持行注释(//)、块注释(/\* \*/)和#开头的注释
- buy, sell, buycover, sellcover

**待实现功能**：

- 增强错误处理，提供更详细的错误信息
- 优化 Token 生成性能
- 当脚本出错的时候，给出具体的提示，包括错误类型、错误位置、错误原因等

### 3.2 语法分析器(Parser)

**功能**：将 Token 流转换为抽象语法树(AST)，验证脚本的语法正确性。

**主要特性**：

- 支持变量声明和赋值(包括复合赋值)
- 支持条件语句(if-else)
- 支持循环语句(for)
- 支持函数定义和调用
- 支持序列变量声明
- 支持交易指令
- 支持返回语句

**待实现功能**：

- 完善语法错误处理
- 支持更多复杂的表达式和语句结构

### 3.3 语义分析器(Semantic)

**功能**：对 AST 进行语义检查，确保脚本符合 TradeBlazer 语法规则。

**主要特性**：

- 检查函数定义是否重复
- 检查变量定义是否重复
- 检查 TradeBlazer 标准函数是否存在(OnInit, OnTick, OnBar)
- 递归检查语句块中的变量使用和函数调用
- 验证变量和函数在使用前已定义
- 验证指标的有效性

**待实现功能**：

- 增强类型检查机制
- 提供更详细的语义错误提示

### 3.4 抽象语法树(AST)

**功能**：表示 TradeBlazer 脚本的语法结构，作为编译器各阶段之间的数据交换格式。

**主要数据结构**：

- **Expr**：表达式类型，包括数值、字符串、布尔值、变量引用、二元运算、一元运算、函数调用、指标引用等
- **Op**：运算符类型，包括算术、比较、逻辑运算符等
- **Statement**：语句类型，包括变量赋值、序列声明、条件语句、循环语句、函数定义、函数调用语句、交易指令、返回语句等
- **Script**：完整脚本，包含多个语句

**待实现功能**：

- 扩展支持更多的表达式和语句类型

### 3.5 解释器(Interpreter)

**功能**：执行 AST 表示的 TradeBlazer 脚本逻辑。

**主要组件**：

- **MarketDataContext**：数据上下文，存储 K 线和 Tick 数据
- **TradingExecutor**：交易执行器，处理交易指令
- **Value**：值类型，表示解释器中的各种数据类型
- **内置函数**：提供常用的内置函数支持

**主要特性**：

- 支持变量和序列的存储和访问
- 支持函数的注册和调用
- 支持 K 线和 Tick 数据的管理
- 支持交易指令的执行
- 支持初始化、Tick 事件和 Bar 事件的处理

**待实现功能**：

- 完善内置函数库
- 增强序列操作功能
- 优化执行性能
- 增加更多的调试功能

src/parser.rs:200-214 的 for 解析把 i++/i+=1 等语法翻译成 \_assign 调用，但解释器在 evaluate_expression 分支 (src/interpreter.rs:433-469) 里没有处理 \_assign。当前代码一旦解析到这种 for 步长就会在执行阶段报 “未定义的函数: \_assign”。需要补上 \_assign 的解释逻辑或在语义检查阶段禁止尚未实现的形式。

将内置函数注册设计得更具扩展性。目前 register_builtin_functions 只是往变量表里塞 Value::Function("Name") 字符串占位，再由 call_function 做 match。可以考虑把内置函数抽象成枚举或 trait 对象，避免字符串匹配、减少复制。
事件初始化阶段 (parse_script) 会直接执行所有顶层赋值表达式，这里面如果引用了指标（例如 var a = Close;）会触发 “没有可用的 Bar 数据”。可以把顶层赋值延迟到真正执行（OnInit/OnBar）时，或改为在 parse_script 阶段只记录表达式，执行放到后面。
