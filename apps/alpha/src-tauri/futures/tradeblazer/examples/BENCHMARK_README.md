# TradeBlazer 编译器性能测试工具

本目录包含用于测试 TradeBlazer 编译器性能的工具和脚本。

## 性能测试文件说明

1. **benchmark.tb** - 一个较大的 TradeBlazer 脚本，用于测试编译和执行性能
   - 包含大量的全局变量、序列变量和函数
   - 实现了多种技术指标计算（MA、RSI、MACD、布林带、ATR、KDJ、ADX等）
   - 包含复杂的数学计算和逻辑判断
   - 设计用于测试编译器的性能极限

2. **run_benchmark.rs** - 一个 Rust 程序，用于实际执行性能测试
   - 读取 benchmark.tb 脚本并执行指定次数
   - 测量编译和执行时间
   - 提供详细的性能统计（平均时间、最小时间、最大时间、标准差等）

3. **BENCHMARK_README.md** - 本说明文件

## 如何运行性能测试

### 方法一：直接运行 Rust 性能测试程序

```bash
cargo run --example run_benchmark
```

### 方法二：单独测试脚本编译时间

```bash
# 测量单次编译时间
cargo run --release -- "examples/benchmark.tb"

# 或者使用 Linux 的 time 命令获取更详细的时间信息
/usr/bin/time -v cargo run --release -- "examples/benchmark.tb"
```

## 性能测试指标说明

执行性能测试后，程序会输出以下指标：

- **总执行次数** - 总共执行了多少次脚本
- **总耗时** - 执行所有测试用例的总时间
- **平均总耗时** - 每次执行的平均总时间
- **平均执行时间** - 每次脚本执行的平均时间
- **最小执行时间** - 最快的一次执行时间
- **最大执行时间** - 最慢的一次执行时间
- **执行时间标准差** - 执行时间的一致性度量
- **吞吐量** - 每秒可以执行的脚本次数

## 自定义性能测试

如果你想自定义性能测试参数，可以修改 `run_benchmark.rs` 文件中的常量：

```rust
const SCRIPT_PATH: &str = "examples/benchmark.tb"; // 脚本路径
const RUNS: u32 = 10000; // 执行次数
const WARMUP_RUNS: u32 = 10; // 预热次数
```

## 注意事项

1. 性能测试可能会消耗大量 CPU 资源，请确保在适当的环境中运行
2. 预热阶段是为了减少 JIT 编译和缓存初始化对测量结果的影响
3. 运行多次测试以获得更准确的平均性能数据
4. 不同硬件环境下的测试结果可能会有显著差异

## 如何创建更大的性能测试脚本

如果你需要测试更大的脚本，可以修改 `benchmark.tb` 文件，添加更多：
- 全局变量和序列变量
- 复杂的函数和计算逻辑
- 嵌套的条件判断
- 循环结构（如果支持）
