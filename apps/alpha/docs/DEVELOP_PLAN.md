# TradeBlazer脚本编译器开发计划

## 1. 项目概述
alpha 是一款侧重于实盘交易的交易的工具。他的特点是：
1. 多端运行. 可以手机运行，可以windows运行，可以 linux运行.
2. 性能极致。此项目注重性能，达到伪高频的水平
3. AI 生成策略. 此项目计划集成AI模型，用于自动生成交易策略.
4. 量化方面，达到生产级水准
5. 交易方面，为交易提供个性化的支持。比如，客户可以提他想要做的哪内交易，我们会根据客户的需求，寻找可能存在的交易机会.




## 2. 系统架构

当前系统采用典型的编译器前端架构，包含以下核心组件：

1. **词法分析器(Lexer)**：将脚本文本转换为Token流
2. **语法分析器(Parser)**：将Token流转换为抽象语法树(AST)
3. **语义分析器(Semantic)**：对AST进行语义检查，验证脚本合法性
4. **抽象语法树(AST)**：表示脚本的语法结构
5. **解释器(Interpreter)**：执行AST表示的脚本逻辑
6. 其他功能
   编译后代码序列化，再加载.
## 3. 核心功能模块

### 3.1 词法分析器(Lexer)

**功能**：将TradeBlazer脚本文本转换为Token序列。

**主要特性**：
- 支持基本关键字：if, else, for, function, return, var, series, true, false
- 支持标识符、数值字面量、字符串字面量
- 支持各类运算符和分隔符,包括，=， +， -， *， /， %， <， >， <=， >=， ==， !=
- 支持行注释(//)、块注释(/* */)和#开头的注释
- buy, sell, buycover, sellcover

**待实现功能**：
- 增强错误处理，提供更详细的错误信息
- 优化Token生成性能
- 当脚本出错的时候，给出具体的提示，包括错误类型、错误位置、错误原因等

### 3.2 语法分析器(Parser)

**功能**：将Token流转换为抽象语法树(AST)，验证脚本的语法正确性。

**主要特性**：
- 支持变量声明和赋值(包括复合赋值)
- 支持条件语句(if-else)
- 支持循环语句(for)
- 支持函数定义和调用
- 支持序列变量声明
- 支持交易指令
- 支持返回语句

**待实现功能**：
- 完善语法错误处理
- 支持更多复杂的表达式和语句结构

### 3.3 语义分析器(Semantic)

**功能**：对AST进行语义检查，确保脚本符合TradeBlazer语法规则。

**主要特性**：
- 检查函数定义是否重复
- 检查变量定义是否重复
- 检查TradeBlazer标准函数是否存在(OnInit, OnTick, OnBar)
- 递归检查语句块中的变量使用和函数调用
- 验证变量和函数在使用前已定义
- 验证指标的有效性

**待实现功能**：
- 增强类型检查机制
- 提供更详细的语义错误提示

### 3.4 抽象语法树(AST)

**功能**：表示TradeBlazer脚本的语法结构，作为编译器各阶段之间的数据交换格式。

**主要数据结构**：
- **Expr**：表达式类型，包括数值、字符串、布尔值、变量引用、二元运算、一元运算、函数调用、指标引用等
- **Op**：运算符类型，包括算术、比较、逻辑运算符等
- **Statement**：语句类型，包括变量赋值、序列声明、条件语句、循环语句、函数定义、函数调用语句、交易指令、返回语句等
- **Script**：完整脚本，包含多个语句

**待实现功能**：
- 扩展支持更多的表达式和语句类型

### 3.5 解释器(Interpreter)

**功能**：执行AST表示的TradeBlazer脚本逻辑。

**主要组件**：
- **DataContext**：数据上下文，存储K线和Tick数据
- **TradingExecutor**：交易执行器，处理交易指令
- **Value**：值类型，表示解释器中的各种数据类型
- **内置函数**：提供常用的内置函数支持

**主要特性**：
- 支持变量和序列的存储和访问
- 支持函数的注册和调用
- 支持K线和Tick数据的管理
- 支持交易指令的执行
- 支持初始化、Tick事件和Bar事件的处理

**待实现功能**：
- 完善内置函数库
- 增强序列操作功能
- 优化执行性能
- 增加更多的调试功能

## 5. 当前重点任务

基于当前代码分析，以下是需要优先完成的任务：

1. **修复序列变量索引访问功能**
   - 问题：当前无法正确使用`[]`运算符访问序列元素
   - 解决方案：完善`_index_access`函数实现，确保正确处理序列索引

2. **完善_method_call函数**
   - 问题：当前_method_call函数存在未定义的问题
   - 解决方案：确保解释器能够正确识别和处理内部特殊函数调用

3. **增强错误处理机制**
   - 问题：当前错误提示不够详细，不利于调试
   - 解决方案：增强各组件的错误处理，提供更详细的错误信息

- 构建工具：Cargo

```

├── Cargo.toml
├── docs/                  # 文档目录

```
